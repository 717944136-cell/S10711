Agent（AI 智能体）

Agent / AI Agent · 大模型课程概念学习资料 ①
🎯 入门→进阶👤 编程初学者📅 2026-09-07

学习目标

  • 能用 1～2 句话说清"什么是 Agent"，并讲明白它与聊天机器人的差别。
  • 能说出 Agent 的核心组成（规划 / 记忆 / 工具）与"感知–决策–行动–反馈"循环。
  • 能举出一个真实应用场景，并说出它的使用边界与风险。

核心问题

  • 同样是 AI，为什么聊天机器人不算 Agent？Agent 到底"多做了什么"？
  • Agent 靠什么把一个大任务一步步做完？做错了会怎样？
  • Agent 可以完全自主吗？边界在哪里？

个人解释（我的理解）

我的记忆锚点是一句话：Agent = 大模型（大脑）＋规划＋记忆＋工具（手脚），在"环境反馈"的循环里自主完成任务。

如果把只会聊天的 ChatGPT 比作"一个很聪明、但坐在原地只接话的顾问"，那么 Agent 就是"被派出去独立办事的实习生"：他拿到一个目标后自己拆步骤、自己查资料、自己动手，做错了根据结果重试，干完了才回来向你汇报。聊天是"一问一答"，Agent 是"领任务→干活→汇报"。

🧭 类比：搜索引擎＝你自己查资料、自己做判断；Agent＝你把整件事交给一个会用电脑的助手，他自己查、自己干、自己核对，遇到不确定再回来问你。差别的关键是：它会不会"动手做事并观察结果"。

两个业界定义帮我校准了理解：

  • OpenAI：Agent 是有 instructions（该做什么）、guardrails（不该做什么）和 tools（能做什么）的 AI 系统，代表用户去采取行动；如果只是生成文本回答、不连接任何系统采取行动，那更接近聊天机器人。
  • Anthropic：Agent 本质上常常"只是 LLM 基于环境反馈在一个循环里调用工具"，实现并不神秘；它的价值主要来自任务选型与工具设计。

核心机制 / 组成

下面是 Agent 工作的一般循环（参考 Anthropic《Building Effective Agents》与 Lilian Weng 的经典综述整理）：

# Agent 主循环（伪流程） 用户目标 / 指令 ──▶ 规划 Planning （拆解子任务 · 自我反思 · 决定下一步） │ ▼ 记忆 Memory：短期＝上下文/对话历史 │ 长期＝向量库/笔记/文件 ▼ 工具 Tools：搜索 · 代码执行 · API · 读写文件 │ ▼ 执行动作 → 得到环境反馈（工具结果/报错） │ 反馈回到上下文，判断：完成了吗？ ├── 没有 → 回到规划，继续循环（可重试、可修正） └── 完成 → 整理结果，交付 / 向人汇报（必要时等待审批）

组成拆解

组成作用例子
规划 Planning把复杂任务拆成可执行步骤；执行中自我反思、调整计划（如 ReAct 的"推理+行动交替"模式）。"先读全部笔记，再提炼要点，最后写周报"
记忆 Memory短期记忆＝当前对话上下文；长期记忆＝可检索的笔记/知识库，让 Agent 跨会话"记得"。上下文窗口、向量数据库
工具 Tools让 Agent 能"动手"：查资料、执行代码、调 API、改文件，把能力从"说话"扩展到"做事"。网络搜索、代码解释器、文件读写

关键点：环境反馈是循环的燃料——工具的真实返回（成功/报错）让模型基于事实判断进展、及时纠错，而不是凭想象一路狂奔（否则错误会不断累积）。Anthropic 还强调：Agent 可以在检查点或遇到阻碍时暂停，把控制权交回给人。

一个具体应用场景

场景：让 Agent 帮我整理一周的学习笔记。我把一个装满课堂笔记的文件夹交给它，说："汇总成一份 Markdown 周报，标出我还没搞懂的概念。"

  1. 规划：Agent 自动列出步骤——遍历文件夹 → 读每份笔记 → 提炼本周主题 → 对"没搞懂的概念"标记并查资料 → 生成周报。
  2. 工具＋反馈：它调用"读文件"工具逐份读取；某份笔记是旧编码读出来是乱码，它根据报错换一种方式重读（纠错）；遇到它也不确定的概念，它联网搜索确认后再写进周报。
  3. 交付：循环结束，输出 `weekly-report.md`，并回来告诉我"有三处概念我标注为存疑，建议你确认"。我审阅后决定是否采纳——这就是"人在回路"。

这不是想象：Anthropic 披露的真实案例包括——用 Agent 做客服（自动查订单、按规则处理退款）和写代码（对着测试结果反复改代码解决 SWE-bench 任务），都是"对话＋行动＋清晰成功标准"的典型场景。

容易混淆的问题 / 使用边界

容易混淆关键区别（一句话）
Agent vs 聊天机器人（chatbot）聊天机器人只生成文本回答；Agent 能调用工具、采取行动、根据环境反馈推进任务。判据：它有没有"做事"的循环。
Agent vs 工作流（Workflow）Anthropic 的区分：Workflow＝由代码预先定义路径去编排 LLM（确定性）；Agent＝由LLM 自己决定路径与步数（动态）。
Agent vs "接了 API 的聊天框"只是背后多了个接口、但没有自主规划与多步行动循环，严格说仍是增强型助手，不是 Agent。
⚠️ 边界提醒：Agent 自主 ≠ 无限信任。
  • 成本与错误累积：自主意味着更多步数、更高成本；一步错可能步步错（compounding errors）。Anthropic 建议先在沙箱环境充分测试。
  • 需要护栏：高影响动作（删数据、转账、发消息）应设 guardrails 与人工审批，保持"人在回路"。
  • 不是所有任务都该用 Agent：路径可预测的固定任务用普通脚本/工作流更便宜、更可靠（Anthropic 原则：先简单方案，复杂到确实需要再升级）。

自测问题

Q1：某应用内嵌了 ChatGPT 帮你写回复，但不调用任何工具、不做多步执行。它算 Agent 吗？
不算。它没有工具、没有"行动→反馈"的自主循环，更接近"增强型 LLM 助手/聊天机器人"。
Q2：按经典综述，Agent 系统的三大组成是什么？
规划（Planning）、记忆（Memory）、工具使用（Tool Use），由 LLM 作为核心控制器（controller）协调。
Q3：Workflow 与 Agent 的关键区别是什么？
控制流归谁决定：Workflow 由代码预定义路径（确定），Agent 由 LLM 在执行中动态决定路径与步数（不确定）。
Q4：为什么工具返回的"环境反馈"对 Agent 很重要？
让模型基于真实结果判断进展与纠错（ground truth），避免脱离现实凭空继续，从而抑制错误累积。
Q5（开放）：举一个"不该用 Agent"的例子。
示例：每天凌晨把日志文件改名归档——路径完全固定、可预测，用普通脚本即可，用 Agent 反而更贵、更不可控。
